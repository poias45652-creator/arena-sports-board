# 三聯盟比分更新穩定性試作

範圍：星準的 CPBL／NPB／KBO 即時比分 API 與比分畫面。以 2026-10-29 的 `main`（`6c385f57e672330ef6e98832ebd0dd2f044da8e4`）為基準；不包含 JSHEN 桌面採集器、其他球種或新的資料來源。

## 行為

- 原本快取到期後，HTTP 讀取必須等整次來源採集及保存完成。現在比分 API 使用 `preferCached`，先回傳同聯盟、同日期的記憶體或資料庫紀錄，原採集工作繼續完成。
- 舊紀錄標為 `stale`／`sourceStale`，原 `source.fetchedAt` 保持不變。更新尚未完成時帶 `refreshing: true`，不宣稱已取得新的來源觀測。
- 沒有可用紀錄時，資料層最多先等待 2 秒，接著回傳明確的更新中狀態；不把缺資料當作休賽。此時間不包含登入驗證、網路傳輸、啟動服務或事件迴圈阻塞。
- 同聯盟、同日期的畫面讀取、背景更新、賽前分析共用原有的單次採集。預設呼叫仍等待驗證完成，賽前分析不會因顯示優化而改用未更新的場況。
- 前台只在更新尚未完成時採用最短 5 秒重查；完成後回到原有 60 秒或 5 分鐘週期。隱藏分頁暫停重查。
- 同日手動更新或網路錯誤保留畫面。另一程序尚在讀取快照而回傳空的更新中結果時，也保留當前同日紀錄。切換聯盟或日期會清除不相符紀錄，延遲回應不能覆蓋新選擇。
- 保留既有賽事撤除、完賽留存、來源時間驗證、登入檢查與 `private, no-store` 設定。

## 驗證

`npm test`：775 項通過、0 失敗、0 跳過。新增的 `npm run test:live-stability` 已納入預設測試，涵蓋 100 項比分與來源回歸測試。

`npm run build`：正式建置與型別檢查通過。

控制條件下的本機比較：先建立有效快取，再使其到期；來源固定延遲 1,200 毫秒；同時發出 100 個讀取。原版回應約 1,202.3 毫秒，修改版先回傳舊快照約 0.5 毫秒；兩版都只發出 1 次刷新採集。修改版的原觀測時間沒有被刷新。這是回傳已保存資料的模擬結果，不是外部來源變快，也不是正式網站端到端效能測量。

新增測試涵蓋來源及儲存服務延遲、初次載入等待上限、100 個讀取共用採集、來源失敗後恢復、跨聯盟／跨日隔離、錯誤時間戳、休賽證據過期、已撤除場次不復活，以及實際前端 effect 和 HTTP route 的行為。

## 實施界線

此版本仍使用同一個 Node 程序內的背景工作；程序停止或主機休眠時不能繼續採集。沒有新增常駐服務、資料庫欄位、部署設定或外部帳號設定，也沒有更換來源或更動推薦模型。

這次是隔離分支的試作，尚未合併或部署。上線後才能量測實際 HTTP 延遲、來源成功率及記憶體使用情況；不能據此認定已解決正式站所有斷線問題。
