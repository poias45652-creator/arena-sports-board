## 先確認：這是原始碼包，還不是 Render 直接覆蓋包

保留目前 GPT 版網站完整程式與既有功能，沒有改成範例或精簡網站。
本版實際使用 Vinext、Vite、Cloudflare Workers 和 D1；登入、資料保存及部分 API 依賴這些環境。
不能把 ZIP 當成 HTML 靜態網站直接上傳，也不能僅在 Render 填入 npm start 就視為完成搬移。
本次沒有建立 Render 服務、修改線上網站或移轉正式資料庫。

## 包含內容

- app、components、hooks：前台、登入、管理後台、四聯盟畫面與互動。
- lib、server、worker：資料來源、機率分析、連線、登入驗證、API 與伺服器邏輯。
- db、drizzle：資料表結構、0000–0012 資料庫迁移與快照；不是正式資料庫備份。
- data、server/research-data、public/history：程式使用的已收集棒球資料、歷史資料與研究結果。
- public：網站品牌、背景、隊標及其他靜態資源。
- scripts、tests、ops、docs：資料整理、回測、測試、操作與背景更新準備文件。
- package.json、package-lock.json、設定檔與空白秘密設定範例 .env.example。
- EXPORT-MANIFEST.json：檔案清單、SHA-256、來源版本與本次去識別修改。

## 帳號授權與刪除（本版新增）

- 使用者以原平台帳號密碼驗證後，沒有網站授權紀錄的普通帳號只會登記為待授權，不會建立網站登入狀態。
- 管理員到 /admin 的「帳號授權管理」，可查看待授權清單、授權使用、不予授權、停用及設定到期日。
- 既有一般帳號若沒有明確授權紀錄，也會被阻擋；既有有效授權會保留。
- 主管理員在平台核驗身分後可初始化管理授權，不能在後台被停用、設定期限或刪除；不會覆寫資料庫中既有的明確限制。
- 「刪除帳號」必須確認，會原子性刪除該帳號的網站登入、授權與來源連線紀錄，立即使原 Cookie 失效。其他帳號不受影響。
- 不會刪除原平台帳號；使用者之後重新核驗平台帳號時，仍须重新取得網站授權。
- 本版登入、授權與刪除相關 28 項測試通過；v172 已发布至原 GPT 網站。

## 安裝與檢查

解壓縮後進入 YJ-Sports-v172 專案目錄。使用 Node.js >=22.13.0；目前腳本以 Linux 或 Windows WSL2 為準，需要 bash、flock、curl、GNU timeout。

```bash
npm run install:ci
npm run build
npm run dev
```

npm run dev 用於本機檢視；正常登入及資料存取還需要建立並初始化 D1 DB 綁定、設定伺服器秘密等。
v172 原始來源已成功建置並發布；ZIP 經過結構、內容完整性與秘密掃描。匯出副本含去識別變更，沒有宣稱已於 Render 啟動驗證。

## 部署到 Render 仍須完成

1. 將 Cloudflare Worker 入口與 Cloudflare 專用 env 引用轉成 Render 可用的 Node 伺服器，配置服務監聽位址與 PORT。
2. 遷移 D1 資料層與查詢介面（prepare、bind、batch 等）到目標資料庫或經授權的遠端資料服務；保留帳號、連線、研究紀錄與預測保存能力。
3. 完整保留 worker/index.ts 的登入與 API 權限檢查，避免移除 Worker 後漏掉保護。
4. Sites 的登入路由與 oai-authenticated-user-* 身分標頭只在其可信平台邊界下使用。外部主機不可直接信任訪客自帶標頭；須移除這個信任路徑，或接上真正會驗證並重寫標頭的認證入口。
5. 為新域名重設 Turnstile 公開 site key、秘密與 hostname 驗證。lib/turnstile.ts 現在綁定原 GPT 網域。
6. 在目標主機設定 TZ_BINDING_KEY 等秘密；依 db/schema.ts 與遷移建立資料表。這份包不含原正式會員資料或其加密授權。
7. 驗證登入、管理員權限、資料來源連線、四聯盟讀取、分析與保存；不能把本機建置成功等同搬移成功。
8. 全天背景更新需另建並實際驗證排程。ops 內的排程只是準備檔，不代表已有服務運作。

歷史資料是既有來源紀錄，不是現在的即時比分，也不是完整正式資料庫匯出。賽前預測留存依既有資料更新触發，尚未啟用全天背景更新。
使用者目前要求不抓中職官網；現行中職 Game Logs 來源遵守此要求。部分更早的研究匯入檔仍保留原始來源標記，保留歷史檔案不代表本次或目前允許新增官網抓取。
